# 产品

## 定位

Idset 管理一台机器上的多个 Git 和 SSH 身份：每个身份有自己的提交署名、SSH 密钥和 Host 别名，按文件夹自动生效。它常驻在托盘里，用纯 Go 和 MyGo 原生 UI 写成，支持 macOS、Windows 和 Linux。

核心约定（见 [ADR 0002](adr/0002-managed-files-and-one-include.md)）：

- `accounts.json` 是唯一的事实来源。每次修改后，从它整体重新生成 Idset 自己的配置文件（下称「托管文件」）。
- 用户的 `~/.ssh/config` 和 `~/.gitconfig` 里只插入一个带标记的块，块里只有一行 Include。标记块以外的内容永远不改。
- 私钥只按路径引用。Idset 不读取、不复制、不上传私钥内容；只有删除身份时用户勾选「同时删除私钥」，才会删私钥文件。

## 范围

按 [roadmap](roadmap.md) 的顺序逐项落地：

- 身份列表，生成 SSH Host 别名、`includeIf "gitdir:"` 规则和 `insteadOf` 地址改写。
- 托盘面板：身份列表、拖入文件夹看匹配结果、绑定和改绑、克隆命令助手。
- 连通性检查和诊断，失败时给出下一步操作。
- 生成密钥、加载到 ssh-agent、复制公钥。
- 从已有的 `~/.ssh/config` 和 `~/.gitconfig` 导入。
- 备份和恢复 `accounts.json`。

不做：云同步、多设备合并、改写用户手写的 `[user]` 或 Host、改写已有提交的作者、托管平台账号登录和 API 调用、私钥口令管理、命令行界面。

## 技术基线

- 纯 Go，MyGo 原生 UI 和原生更新插件（[ADR 0001](adr/0001-pure-go-native-ui.md)）。没有 WebView，生产代码没有 cgo。
- 调用系统的 `git`、`ssh`、`ssh-add`、`ssh-keygen`（[ADR 0004](adr/0004-system-ssh-and-git.md)）。每个命令带超时，标准输入接空，参数用列表传。环境变量在当前进程环境上追加，不替换。
- 界面语言：英文和简体中文。默认跟随系统，设置里可以改；改了立即生效，不用重启。
- 版本号只写在 `mygo.json`。

## 文件和目录

三个平台都用同一套相对主目录的路径，这样 `Include` 和 `includeIf` 里可以写 `~`，配置文件也能放进 dotfiles 仓库：

| 用途 | 路径 |
|---|---|
| Idset 目录 | `~/.config/idset/`（Windows 是 `%USERPROFILE%\.config\idset\`） |
| 身份数据 | `~/.config/idset/accounts.json` |
| 界面偏好 | `~/.config/idset/settings.json` |
| 托管文件 | `~/.config/idset/ssh_config.managed`、`gitconfig.managed`、`gitconfig-<ID>.managed` |
| 备份 | `~/.config/idset/backups/` |
| 用户的 SSH 配置 | `~/.ssh/config` |
| 用户的 Git 配置 | `~/.gitconfig` |
| 新生成的密钥 | `~/.ssh/` |

- 目录按需创建，第一次保存身份之前不写用户的配置文件。
- 所有写入都是原子的：写同目录的临时文件再替换。
- 新建的 `~/.ssh/config` 和托管文件在 macOS、Linux 上权限是 `0600`，目录 `0700`；Windows 上继承用户目录的权限，默认只有当前用户和系统能访问。已有的文件保留原来的权限。
- 目标路径是符号链接时，备份、恢复和删除私钥都拒绝操作。写 `~/.ssh/config` 和 `~/.gitconfig` 时跟随符号链接写到真实文件，因为 dotfiles 常用符号链接管理；文件原来用 CRLF 换行就保持 CRLF。

## 数据模型

### 身份

| 字段 | 说明 |
|---|---|
| `id` | UUID，不变 |
| `label` | 显示名，可以为空，界面显示「（未命名）」 |
| `provider` | `github`、`gitlab`、`gitea`、`custom`，缺省 `github` |
| `hostName` | 真实主机名。非 `custom` 时由平台决定，用户不填；`custom` 必填 |
| `sshPort` | 端口。非 `custom` 只能是 22 或 443，缺省 443；`custom` 可以是 1–65535，缺省 22 |
| `sshAlias` | SSH Host 别名，例如 `github-work`。检查、匹配和克隆助手都靠它 |
| `username` | 托管平台上的用户名，只用于显示和检查结果对照 |
| `keyPath` | 私钥路径。主目录下的存成 `~/…`，其他存绝对路径 |
| `keyFingerprint` | `SHA256:…`，生成或关联密钥时写入，可以没有 |
| `gitUserName`、`gitUserEmail` | 提交署名 |
| `scope` | `global`，或 `gitdir` 加一组路径 |
| `urlRewrites` | 一组 `{from, to, push}`。`push` 为真时生成 `pushInsteadOf`，否则 `insteadOf` |
| `color` | 预设名（`blue`、`green`、`orange`、`red`、`purple`、`yellow`）或 `#RRGGBB` |
| `notes` | 备注 |
| `createdAt`、`updatedAt`、`lastUsedAt` | 时间。`lastUsedAt` 可以没有；只更新它时不改 `updatedAt` |

平台的默认值：

| provider | 显示名 | 22 端口的主机 | 443 端口的主机 | `HostKeyAlias` | SSH 公钥设置页 |
|---|---|---|---|---|---|
| github | GitHub | `github.com` | `ssh.github.com` | 443 时为 `github.com` | `https://github.com/settings/keys` |
| gitlab | GitLab | `gitlab.com` | `altssh.gitlab.com` | 443 时为 `gitlab.com` | `https://gitlab.com/-/user_settings/ssh_keys` |
| gitea | Gitea | `gitea.com` | 不支持，只能用 22 | 无 | `https://gitea.com/user/settings/keys` |
| custom | 自定义 | 用户填写 | 用户填写 | 无 | 无，只提供复制公钥，不编造链接 |

保存前的校验：

- `sshAlias` 只能用字母、数字、`.`、`_`、`-`，不能和其他身份重复，也不能等于某个平台的真实主机名。可以留空，留空的身份不生成 Host 块。
- `keyPath` 可以留空，留空的身份不生成 Host 块和 `core.sshCommand`。
- `custom` 必须有 `hostName`。
- 最多一个全局身份。已有全局身份时，再把别的身份设成全局，提示先把 <名称> 改成限定。
- 除备注外，字段里不能有换行；密钥路径和 `gitdir` 路径里不能有双引号。防止往生成的配置里注入额外指令。
- 颜色是六个预设名之一或 `#RRGGBB`。
- 校验失败时，在对应字段下面显示原因，不保存。只拦这次修改新引入的问题：`accounts.json` 被手改出的问题（比如多个全局身份）不妨碍其他修改，由诊断提示。

### 范围

- `global`：没有 `gitdir` 规则命中时生效。最多一个。
- `gitdir`：一组路径，每条生成一个 `includeIf`。路径列表可以为空：解绑最后一条后仍是 `gitdir`，不会变回 `global`，免得悄悄接管所有仓库。
- 路径的存储形式：去掉首尾空白，主目录下的写成 `~/…`，末尾补 `/`。Windows 上存成正斜杠和盘符，例如 `C:/work/`。

### accounts.json

```json
{
  "accounts": [
    {
      "color": "#3A7BD5",
      "createdAt": "2026-08-01T10:00:00Z",
      "gitUserEmail": "bob@example.com",
      "gitUserName": "Bob",
      "id": "22222222-2222-2222-2222-222222222222",
      "keyFingerprint": "SHA256:AbCdEf",
      "keyPath": "~/.ssh/id_work",
      "label": "work",
      "lastUsedAt": "2026-08-20T09:30:00Z",
      "notes": "",
      "provider": "github",
      "scope": {
        "gitdir": {
          "paths": [
            "~/work/",
            "~/src/new-app/"
          ]
        }
      },
      "sshAlias": "github-work",
      "sshPort": 443,
      "updatedAt": "2026-08-20T09:00:00Z",
      "urlRewrites": [
        {
          "from": "https://github.com/example-org/",
          "push": false,
          "to": "git@github-work:example-org/"
        }
      ],
      "username": "bob"
    }
  ],
  "version": 1
}
```

- 键按字母排序、缩进两格输出，时间是 UTC 的 RFC 3339。没有值的可选字段省略。
- `{"global": {}}` 表示全局范围。
- 文件里只有私钥的路径和指纹，没有私钥内容。
- 缺少 `provider` 时按 `github`，缺少 `sshPort` 时按该平台的默认端口。
- 文件不存在：身份列表为空，不创建文件。
- 文件读不出来（JSON 错误、版本比当前程序新、缺少 `id` 或 `scope`、未知的平台）：进入只读状态。面板说明文件读不出来和具体原因，给出路径、「重新读取」和「从备份恢复」入口；在用户恢复备份或手动修好之前，任何写操作都不可用，绝不覆盖这个文件。

### 存储顺序

身份按添加的顺序存储。存储顺序决定 `includeIf` 在同等具体度时的先后，也决定账户窗口第一次打开时默认选中谁。

### 备份

- 文件名 `accounts.json.<yyyyMMdd-HHmmss>`，UTC。同一秒冲突时加 `-1`、`-2`。
- 只在两种时候自动备份：新增身份之前（文件已存在时，包括导入、生成密钥时新建、从拖入的文件夹新建），以及恢复备份之前。编辑、删除、绑定都不备份。
- 每次备份后只保留最新的 10 份。
- 恢复：先备份当前文件，再把备份复制到临时文件并原子替换，然后重新生成托管文件。

## 生成配置

生成是纯函数：输入身份列表和生成时间，输出三类文件的内容，同样的输入同样的输出。写文件只在一处：写两个主文件，删掉目录里本次没有生成的 `gitconfig-*.managed`，再写子文件，最后确保两个 Include 标记块存在。

几乎所有修改身份的操作之后都重新生成：保存、删除、导入、恢复、绑定、解绑、改绑、撤销、诊断修复、关联密钥、加地址改写。

### ssh_config.managed

```
# AUTO-GENERATED BY Idset. Edit in the app or in accounts.json.
# Last regenerated: 2026-08-22T08:00:00Z

Host github-work
	HostName ssh.github.com
	Port 443
	User git
	IdentityFile "~/.ssh/id_work"
	IdentitiesOnly yes
	HostKeyAlias github.com

```

- 每个有别名和密钥路径的身份生成一个 Host 块，缩进用 Tab，块后空一行。
- `HostName`、`Port`、`HostKeyAlias` 按上面的平台默认值表填写；`custom` 用身份自己的主机名和端口，不写 `HostKeyAlias`。
- `IdentityFile` 加双引号，路径里有空格也能用。

### gitconfig.managed

依次写：文件头、全局 `[user]`、地址改写、`includeIf`。

```
[user]
	name = Alice
	email = alice@example.com

[url "git@github-work:example-org/"]
	insteadOf = https://github.com/example-org/
	insteadOf = git@github.com:example-org/

[includeIf "gitdir:~/"]
	path = ~/.config/idset/gitconfig-11111111-1111-1111-1111-111111111111.managed

[includeIf "gitdir:~/work/"]
	path = ~/.config/idset/gitconfig-22222222-2222-2222-2222-222222222222.managed
```

- 全局 `[user]`：来自全局身份，没有署名就不写。`accounts.json` 被手改成多个全局身份时，用存储顺序最后一个有署名的，和 git 实际生效的一致。
- 地址改写：收集所有身份的规则（包括限定范围的身份，改写对所有仓库都生效），去掉 `from` 或 `to` 为空的，按 `to` 分组，组按 `to` 升序输出，组内按身份存储顺序和规则顺序，完全相同的规则只写一次。`push` 为真的写 `pushInsteadOf`。
- `includeIf`：每条路径一个块，指向这个身份唯一的子文件。
- 值里有 `#`、`;` 或首尾空白时整体加双引号；`\`、`"` 和 Tab 一律转义。

### includeIf 的顺序

git 会应用所有命中的 `includeIf`，按文件里的顺序，后写的值覆盖先写的，和具体度无关。所以要让「最具体的路径胜出」，就必须把最具体的写在最后：

1. 路径段数少的在前；
2. 段数相同，字符串短的在前；
3. 再按身份存储顺序；
4. 再按路径字符串。

匹配文件夹时用同一个顺序，命中的块里最后一个就是 git 实际会用的身份。这个规则要有调用真实 `git` 的测试。

- macOS 和 Linux 写 `gitdir:`。Windows 写 `gitdir/i:`，路径用正斜杠和盘符，和 Windows 的文件系统一样不区分大小写。
- 同一个身份里规范化后重复的路径只写一次，空路径跳过。

### gitconfig-&lt;ID&gt;.managed

只给至少有一条有效 `gitdir` 路径的身份生成：

```
# AUTO-GENERATED BY Idset for account 22222222-2222-2222-2222-222222222222 (work)

[user]
	name = Bob
	email = bob@example.com

[core]
	sshCommand = ssh -i \"/home/bob/.ssh/id_work\" -o IdentitiesOnly=yes
```

- 没有署名就不写 `[user]`，没有密钥路径就不写 `[core]`。
- `sshCommand` 由 shell 解析，引号里的 `~` 不会展开，所以写展开后的绝对路径并加引号（Windows 上用正斜杠）。托管文件每台机器各自生成，不需要可移植。`ssh_config.managed` 里的 `IdentityFile` 和 `Include` 由 ssh 自己展开 `~`，保留 `~` 形式。

### Include 标记块

标记：

```
# --- idset managed ---
# --- idset managed end ---
```

- `~/.ssh/config`：块放在文件最前面，因为 ssh 用第一个命中的 Host。块里是 `Include "~/.config/idset/ssh_config.managed"`，块后空一行，再接原来的内容。
- `~/.gitconfig`：块追加在文件末尾，因为 git 后写的值覆盖先写的。块里是 `[include]` 和 `path = ~/.config/idset/gitconfig.managed`。这意味着托管的全局 `[user]` 会覆盖用户手写的 `[user]`。
- 已有标记块时，比对块的内容，不一样就原地替换，一样就不写，文件字节不变。
- 移除：删掉第一个开始标记到其后第一个结束标记（含），连同结束标记后紧跟的空行。找不到结束标记就不动。移除后，下一次重新生成会把块加回来，界面上要说明这一点。

## 拖入文件夹

托盘图标不接受拖放（[ADR 0003](adr/0003-drop-zone-in-tray-window.md)），拖放发生在面板里。面板里也有「选择文件夹…」按钮，用系统的目录选择框，效果和拖入一样。只接受目录，拖入多个时取第一个。

### 匹配

1. `git -C <目录> rev-parse --show-toplevel`。失败就是「不是 Git 仓库」。
2. 读 `remote.origin.url`，读不到再用 `git ls-remote --get-url origin`。只用来预填克隆助手和改地址命令，不影响匹配。
3. 有 `gitdir` 路径命中仓库根目录：按上面的顺序，最后一个命中的身份就是结果。
4. 没有命中：有全局身份，结果就是它（多个时取存储顺序最后一个，和生成的 `[user]` 一致）；没有全局身份，结果是「没有匹配」。

判断命中时，仓库根目录和路径都展开 `~`、解析符号链接（macOS 的 `/var` 和 `/private/var` 视为相同），再把仓库根目录拼上 `/.git` 做前缀比较。Windows 上不区分大小写。

匹配结果在面板关闭后保留，只在下一次拖入、点结果卡片上的关闭按钮、或解绑后重新匹配时替换。匹配成功算一次「使用」，更新这个身份的 `lastUsedAt`。

### 结果卡片

所有结果卡片都分两段：上段是拖入的路径（仓库根目录，不是仓库时是拖入的路径）和操作按钮，下段是结论。

**已匹配**：

- 上段：仓库根目录，复制完整路径的按钮（复制后短暂显示「已复制」），清除按钮。
- 下段：身份的首字母徽章、身份名和「Git 在这里用这个身份」；下面三行「别名」「邮箱」「生效目录」（「全局」或列出各条 `gitdir` 路径）。
- 连通性检查有问题时，卡片边框随严重度变成警告或错误色。
- 署名不一致（见下面的「身份核对」）：列出每一条发现，按最高严重度着色。卡片上不放修复按钮，修复只在诊断里出现。
- 远程地址是 HTTPS 时：一行「远程地址是 HTTPS」和「复制改地址命令」。
- 克隆助手（有别名时）。
- 操作：在系统文件管理器里打开；「解绑」（只有这个身份的 `gitdir` 里正好有这个文件夹本身时才显示，父目录不算）；「改绑到」菜单，列出其他身份。

**多个身份覆盖同一目录**（至少两个不同身份的 `gitdir` 命中）：显示在已匹配卡片上方。按 git 读取的顺序列出每个身份和它命中的路径，标出 git 实际会用哪个、哪些被覆盖。两个操作：「这里只用 <胜者>」，把这个文件夹的精确路径加给胜者（胜者已经有这条路径时不显示这个按钮）；「从 <败者> 去掉 <路径>」，删掉败者命中的那一条路径。

**没有匹配**：

- 原因一行，和「绑定到」列表：每个身份一行，已有 `gitdir` 路径的写明「已有 <路径> · 会再加一条」。点一下就绑定，不用确认。
- 「新建身份并绑到这里」：打开账户窗口，新建草稿的范围就是这个文件夹，署名从 `git config --global` 预填，颜色取第一个没用过的预设色。只有保存的正是这个草稿时，才自动重新匹配这个文件夹。

**旧路径失效**（没有匹配时）：拖入的文件夹像是某条已经不存在的 `gitdir` 路径改了名或挪了位置时，在上方提示「<身份> 还指向 <旧路径>，那里已经不在了」，提供「改成这次的路径」和「保留旧路径」。

- 候选：和拖入的文件夹父目录相同（改名），或者最后一级目录名相同、不区分大小写（挪位置）。磁盘上还存在的路径永远不算失效。父目录是 `/` 或拖入的就是主目录时没有候选。
- 多个候选时：改名优先于挪位置，身份名和拖入的目录名相同的优先，再按存储顺序和路径。只提示一个。
- 改成新路径时原位替换，其他路径和顺序不变；新路径已在列表里时直接删掉旧的。

**不是 Git 仓库**：只有原因一行，不能绑定。

**不是文件夹**（拖入的是文件，或者路径已经不存在）：「只能查看文件夹」。

**查看中**：后台运行 `git` 时，卡片显示转圈和「正在查看 <路径>…」。查看期间又拖入新的文件夹，以最后一个为准，前一个的结果丢弃。

**运行不了 `git`**（没装或超时）：卡片用 `Danger` 边框，写「无法运行 git：<原因>」。

所有结果卡片右上角都有清除按钮。显示路径时，主目录写成 `~`，包括主目录经过符号链接解析后的形式（`git` 返回的是解析后的路径）。

### 绑定、解绑、改绑和撤销

- 绑定：文件夹转成存储形式，追加到身份的 `gitdir` 列表，不替换已有路径。已经被这个身份的某条路径覆盖时不改，提示被哪条路径覆盖。全局身份也列在绑定列表里，点了先确认「绑定后 <名称> 只在这个文件夹生效，不再全局生效」，确认后它变成只有这一条路径的限定身份。
- 解绑：只删和这个文件夹完全相同的那条路径。
- 改绑：从当前身份解绑这个文件夹，再绑定到目标身份，只重新生成一次。目标身份已经覆盖这个文件夹时，整个改绑都不改，提示被哪条路径覆盖。
- 绑定、改绑、「这里只用 <胜者>」之后，卡片底部出现 5 秒的「已绑到 <身份> · 撤销」。撤销把涉及的身份恢复成操作前的样子。倒计时按绝对时间算，关掉再打开面板不会续命。解绑没有撤销。
- 这些操作都算一次「使用」。

### 身份核对

匹配成功后，在仓库里读实际生效的 `user.email` 和 `core.sshCommand`，和匹配到的身份对照：

| 情况 | 严重度 | 说明 |
|---|---|---|
| 仓库没有 `user.email` | 警告 | 提交没有作者 |
| `user.email` 属于另一个身份 | 错误 | 提交会署名为 <邮箱>（<身份>） |
| `user.email` 不属于任何身份 | 警告 | 提交会署名为 <邮箱>，没有身份拥有这个邮箱 |
| `core.sshCommand` 用 `-i` 指定了别的密钥 | 错误 | 推送会用 <路径> |

身份没填邮箱时不检查邮箱；没填密钥路径时不检查密钥。邮箱比较忽略大小写和首尾空白。

### 改地址命令

远程地址以 `https://` 或 `http://` 开头，并且能改写成这个身份的 SSH 地址时，生成 `git remote set-url origin git@<别名>:<路径>.git`。路径保留多级子组，去掉末尾的 `/`，确保以 `.git` 结尾。

### 克隆助手

输入 `owner/repo`、完整地址或整条 `git clone …` 命令，输出 `git clone <SSH 地址>`；解释不了就禁用复制按钮。按顺序：

1. 没有别名或输入为空：无结果。
2. 以 `git clone` 开头且至少三个词：取最后一个词。
3. `owner/repo` 简写（允许多级子组）：`git@<别名>:<路径>`，补 `.git`。
4. 已经是 `git@<别名>:` 开头：原样。
5. 改写规则：身份自己的规则，加上平台的默认规则（`https://<主机>/`、`http://<主机>/`、`git@<主机>:`、`ssh://git@<主机>/` 都改写成 `git@<别名>:`，和自己的规则重复的不加）。取最长命中的前缀替换。
6. 兜底：从任意 `user@host:path` 或带协议的地址里取出路径，生成 `git@<别名>:<路径>.git`。

示例：

| 输入 | 身份 | 输出 |
|---|---|---|
| `org/repo` | 别名 `github-work` | `git clone git@github-work:org/repo.git` |
| `https://github.com/org/repo.git` | github | `git clone git@github-work:org/repo.git` |
| `git clone git@github.com:org/repo.git` | github | `git clone git@github-work:org/repo.git` |
| `git@gitlab.com:group/sub/project.git` | gitlab，别名 `gitlab-work` | `git clone git@gitlab-work:group/sub/project.git` |
| `git@github.com:org/repo.git` | custom，别名 `corp-git` | `git clone git@corp-git:org/repo.git` |

- 已匹配卡片上，输入框预填远程地址里的 `owner/repo`。
- 按身份记住上次成功复制时的 owner 前缀（例如 `acme/`），没有预填时用它。裸仓库名不覆盖记住的前缀。存在 `settings.json`。
- 回车等于点复制。复制成功算一次「使用」。

  - 头部：颜色（六个预设色和十六进制输入）、标题、「全局」或「限定」标记。

  - 时间：创建、更新、最近使用。

## 诊断

### 连通性检查

- 对每个有别名的身份运行 `ssh -T -o BatchMode=yes -o ConnectTimeout=5 git@<别名>`，并发执行。完全走用户的 SSH 配置，和 `git push` 时一样。只检查 Idset 管理的身份。
- 按平台识别成功：GitHub `Hi <用户名>!`；GitLab `Welcome to GitLab, @<用户名>!`；Gitea `Hi there, <用户名>!`。用户名要合法（字母、数字、`-`、`_`、`.`，1–39 个字符），不合法的按失败处理，防止伪造的横幅。`custom` 没有统一的成功提示：没有下面任何一种失败输出就算成功，不显示用户名。
- 失败原因按输出（忽略大小写）归类：`permission denied` → 认证被拒；`could not resolve hostname` → 找不到主机；`connection refused` → 连接被拒；`timed out` → 超时；`host key verification failed` → 主机密钥不符；`no such identity`、`no such file` → 密钥文件不存在；其他取第一行非空输出，最多 80 个字符。
- 结果缓存在内存里 10 分钟：成功的不自动重查；失败的过了 10 分钟才重查。面板打开时先用缓存显示，不从「未检查」闪到「检查中」。底部「重新检查」全部强制重查；问题条上的「再检查一次」只重查这一个。

### 密钥状态

只对检查失败的身份收集：

- 私钥文件是否存在（不存在就不再运行任何命令）。
- ssh-agent 是否可用、里面有哪些指纹：`ssh-add -l -E sha256`。
- 私钥有没有口令：`ssh-keygen -y -P "" -f <私钥>`，失败且输出含 `incorrect passphrase` 就是有口令。
- 指纹：优先用存储的 `keyFingerprint`，否则读 `.pub` 文件。

### 问题条

失败按顺序归类，每类有固定的下一步：

| 问题 | 条件 | 操作 |
|---|---|---|
| 私钥不存在 | 有密钥路径但文件不存在 | 生成密钥（打开设置 → 密钥） |
| 密钥已锁定 | agent 可用、私钥有口令、agent 里没有它 | macOS：用钥匙串解锁（`ssh-add --apple-use-keychain`，`SSH_ASKPASS_REQUIRE=never`，不弹提示）。其他平台：显示要在终端运行的 `ssh-add` 命令和复制按钮 |
| 连不上主机 | 找不到主机、连接被拒、超时、主机密钥不符 | 无 |
| 认证被拒 | 其他失败 | 复制公钥；打开 <平台> 的 SSH 设置页（`custom` 没有） |
| 远程地址是 HTTPS | 检查成功，这个身份是当前匹配结果，远程是 HTTPS，身份自己的改写规则改不了它 | 添加平台默认改写 |

除最后一类外都有「再检查一次」。解锁成功后自动再检查一次。复制公钥时 `.pub` 不存在或为空，就说明原因，不往剪贴板写空内容。

### 诊断汇总

面板底部汇总所有问题，只说明情况，不重复问题条上的按钮：

| 代码 | 严重度 | 条件 | 修复 |
|---|---|---|---|
| NET001 | 错误 | 某个身份检查失败 | 只提示「运行 `ssh -vT git@<别名>` 排查」 |
| SSH001 | 警告 | 用户的 `~/.ssh/config` 里有和 Idset 别名同名的 Host | 只提示：Idset 的块在最前面，会先生效；建议删掉手写的那个 |
| GIT001 | 按核对结果 | 当前匹配的身份核对有发现 | 限定范围的身份：「重新生成托管配置」；全局身份：只提示设置邮箱或加 `gitdir` 范围 |
| GIT002 | 错误 | `accounts.json` 里有多个全局身份（只可能来自手改） | 只提示：生效的是 <最后一个>，把其余的改成限定 |

- 修复只改 Idset 自己的文件，不改 `~/.ssh/config` 里用户写的内容。
- 没有问题时只显示一行「配置正常」；还没跑完时不显示。
- 有问题时显示「1 个错误 · 2 个警告」，可展开。问题集合变了自动展开，没变保持用户上次的展开状态。
- 切换语言后重新生成文案。

## 密钥

### 生成

设置 → 密钥：

- 类型：Ed25519 或 RSA 4096。平台（影响结果页的提示和设置页链接）。文件名，默认 `id_idset`。注释，默认是第一个身份的邮箱。
- 文件名只能用字母、数字、`.`、`_`、`-`，不能以 `.` 开头，不能含 `..`。注释里的换行替换成空格。
- 私钥或公钥已存在就报错，绝不覆盖。
- `ssh-keygen -t ed25519 -C <注释> -f <路径> -N ""`；RSA 是 `-t rsa -b 4096`。生成的私钥没有口令，结果页说明以后可以用 `ssh-keygen -p` 加。
- 结果页：公钥文本和复制、路径、指纹、去平台添加公钥的说明、打开平台设置页、在文件管理器里显示、「用于身份」。
- 「用于身份」：选一个已有身份，或新建一个（邮箱取注释，平台取所选）。只写入路径和指纹。取消不改任何身份，密钥文件留在 `~/.ssh/`。

## 导入

### 读取

- `~/.ssh/config` 和它一级 `Include` 的文件（展开 `~`，支持通配符，相对路径按 `~/.ssh/` 解析）。保留原始文本，解析后能逐字节还原。不处理 `Match` 块。
- Git 用 `git config --global --list -z` 读取，所以 `~/.gitconfig`、`$XDG_CONFIG_HOME/git/config` 和 Windows 上的位置都由 git 自己决定。读 `user.name`、`user.email`、`core.sshCommand`、`url.*.insteadOf`、`url.*.pushInsteadOf`、`includeIf.*.path`，并读取每个 `includeIf` 指向的文件里的身份和改写规则（不再往下跟）。

### 识别

对每个 SSH Host：

1. 端口：写了 443 或 `HostName` 是平台的 443 主机 → 443；写了 22 或没写 → 22；其他端口 → 平台为 `custom`，保留端口。
2. 平台：按 `HostName` 认出 github、gitlab、gitea，认不出就是 `custom`，主机名取 `HostName`。
3. 密钥路径：`IdentityFile`，主目录下的存成 `~/…`。
4. 署名：先找 `core.sshCommand` 里用了这个密钥的 git 身份，连同它的 `includeIf` 条件（`gitdir:` 开头的变成 `gitdir` 范围）。找不到时，如果别名就是平台主机名，用无条件的全局身份。
5. 改写规则：`to` 里有 `@<别名>:` 或 `@<别名>/` 的，保留 `insteadOf` 和 `pushInsteadOf` 的区别。

密钥路径相同且署名兼容的候选合并成一个，第一个别名作为身份的别名。全局身份最多一个：已有全局身份，或者候选里有多个全局身份时，只有第一个（没有已有的话）保持全局，其余作为没有路径的限定身份导入，列表里标「导入为限定」，之后再绑定文件夹。Idset 自己生成的 Host 也会被读到，标成「已存在」。

### 界面

- 每个候选一行复选框：名称（没有就用别名）、`别名 · 邮箱`。别名已经存在的标「已存在」，默认不勾。
- 「导入 N 个身份」。逐个新增（每个都会触发备份），然后重新生成，选中第一个导入的身份。
- 没有候选：「在现有的 SSH 和 Git 配置里没找到身份」。

| 项 | macOS | Windows | Linux |
|---|---|---|---|
